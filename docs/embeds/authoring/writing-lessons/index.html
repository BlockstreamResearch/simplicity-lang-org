Writing lessons

Lessons are plain Markdown in src/content/docs/tutorial/. Add a .md file, give it frontmatter, write prose. The sidebar picks it up automatically; sidebar.order controls position.

There are no imports, no component tags, and no registry to update.

Making a snippet runnable

Section titled “Making a snippet runnable”

Add run to the fence’s language tag:

That is the entire mechanism. The reader gets an editor, a Run button, a Reset button, and an output pane. They can edit the code and re-run it.

A fence without run stays an ordinary highlighted code block — use that for fragments and for code you are only discussing.

Flags

Section titled “Flags”

Flags are comma- or space-separated and order does not matter.

FlagEffect
runRequired. Makes the snippet runnable.
title="…"Caption above the editor.
readonlyReader can Run but not edit. Use sparingly — editing is how people learn.
expect=compile-errorThis snippet is supposed not to compile.
expect=run-errorThis snippet is supposed to compile, then fail at runtime.
txRun against a real Liquid testnet transaction (see below).
txid="…"Which transaction to prepopulate. Required with tx.
input=NWhich input the test harness runs against. Default 0.

simf works as an alias for simplicityhl.

Transaction-backed snippets

Section titled “Transaction-backed snippets”

By default a snippet runs against a placeholder transaction, so introspection jets return meaningless values. Add tx and the snippet gets a transaction id field and an input selector, and runs against the real thing:

The reader’s browser fetches the transaction from the public Liquid testnet explorer, along with every transaction its inputs spend from — the spent outputs are what carry the amounts and assets. Nothing is proxied through a server of ours.

Adding a fixture is mandatory. The test harness runs tx snippets offline against checked-in fixtures, so CI neither depends on the explorer being up nor changes behaviour when it is reorganised. A tx snippet whose transaction has no fixture fails the build with instructions rather than being skipped. To add one:

All prev-*.hex files are supplied to every run and matched by txid, so extras are harmless.

What is real and what is not

Section titled “What is real and what is not”

Real: amounts, assets, outpoints, sequences, locktime, version, and every input and output.

Not real: the internal key, tapleaf version, and tappath. The reader’s edited program has a different CMR than whatever actually locked the coin, so there is no genuine taproot spend path to model, and those jets return placeholders. Say so in the lesson if you rely on them.

Also still unavailable: programs needing witness values, since there is no witness-editing UI.

Snippets are tested

Section titled “Snippets are tested”

Every run snippet in every page is compiled and executed by crates/simptut-wasm/tests/tutorial_snippets.rs:

A snippet that stops compiling fails the build rather than surprising a reader. This is why expect= exists: a lesson that deliberately shows broken code must say so, otherwise the harness reports it as a regression.

When you write a snippet you expect to fail, run the test suite and read the message it produces — that message is what your reader will see, so it is worth checking that it actually teaches something.

What snippets can and cannot do

Section titled “What snippets can and cannot do”

Snippets compile and execute a full program — a fn main() — on the Simplicity bit machine.

Consequences worth knowing before you plan a lesson:

  • Introspection jets need the tx flag. Without it the environment is a placeholder and jets like jet::current_amount return meaningless values. See “Transaction-backed snippets” below.
  • Programs needing witness values cannot run. There is no witness-editing UI, so a program declaring unsatisfied witnesses fails with a message naming them. Lessons on witnesses need that UI first.
  • Programs are predicates. There is no return value to display — a program either satisfies its assertions or does not. Use dbg! to surface intermediate values.

Showing values

Section titled “Showing values”

dbg!(expr) returns expr unchanged and reports the value it saw in the output pane. Because it is transparent, you can wrap any subexpression without restructuring the code, and it does not affect the CMR.

Local development

Section titled “Local development”

The WASM compiler is a build artifact under src/wasm/pkg/ and is not committed. Run npm run build:wasm once before your first npm run dev.
