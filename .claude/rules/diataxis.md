# Diátaxis as an organizing principle

This project treats the [Diátaxis](https://diataxis.fr/) framework as a useful
aspirational organizing principle for documentation — not a rigid rulebook, and not
something to force onto every page regardless of fit.

Diátaxis identifies four distinct purposes documentation can serve:

- **Tutorials** — learning-oriented; a lesson that takes a newcomer through doing
  something, building confidence and orientation rather than covering every option.
- **How-to guides** — task-oriented; steps for accomplishing a specific goal a reader
  already knows they want, assuming basic competence.
- **Reference** — information-oriented; accurate, complete, neutral description of the
  thing itself (an API, a jet, a syntax form), organized for lookup rather than reading
  start to end.
- **Explanation** — understanding-oriented; discussion of why something is designed the
  way it is, background, and context that isn't needed to complete a task.

When creating or substantially editing documentation:

- Identify which of the four purposes the page is primarily serving, and keep its
  content consistent with that purpose. A reference page shouldn't carry persuasive
  asides; a tutorial shouldn't bury its steps in exhaustive option coverage; a how-to
  guide shouldn't stop to explain design rationale a reader didn't ask for.
- If an existing page is inconsistently serving more than one purpose (e.g., a
  "quickstart" that is half tutorial and half reference), suggest splitting it into
  separate documents, each serving one purpose — but raise this as a proposal rather
  than restructuring unilaterally, since splitting existing pages affects navigation,
  links, and reader habits.
- When surveying a topic for documentation gaps, note — where feasible and useful —
  which of the four quadrants are covered and which are missing. This is a prompt to
  notice gaps, not a mandate that every topic needs all four forms of coverage.
